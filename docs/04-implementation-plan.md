# 4. 단계별 구현 계획

기존 README.md·레너드.jpg를 유지하고 현재 루트에 앱을 추가한다. 0단계 자료 대조를 완료했으며 후속 구현과 외부 설정 의존성을 구분한다. 이 계획은 아직 실행된 기능 목록이 아니다.

| 단계 | 구현 내용 | 완료 검증·의존성 |
|---|---|---|
| 0 근거 정리 — 완료 | 수행 20쪽·발표 29쪽 전체/부록·이미지 3장 확인, 대응표·설계 수정 | docs/00-reference-review.md에 근거와 충돌 결정 기록 |
| 1 앱 기반 | 공식 문서 확인 후 Next.js/TS 초기화, 환경 검증, 타입화 API 계약, SDK 버전 고정·lockfile | 설치·build·typecheck 통과; 설정 미완료 상태 실제 표시 |
| 2 사용자·자료 | Supabase 마이그레이션/RLS/Storage, SSR Auth, 파일·텍스트 등록/검색/수정/삭제 | 두 계정 격리, 실제 업로드·저장·검색, 비인가 서명 URL 거절 |
| 3 분석·검토 | 추출, 대상 미리보기/동의, 서버 Gemini, 작업 상태/재시도, 제안 편집·확정 | 실제 API 응답; 무동의 호출 없음; 원본/확정 데이터 보존 |
| 4 경험·보완 | 경험 CRUD, 임베딩+키워드 검색·최대 5개 관계 판정·학생 확인, 근거 위치, 그래프·관심사/패턴·기록 상태·보완 | 근거 조회·학생 수정·버전 충돌, 점수화 없음 |
| 5 목적·포트폴리오 | 고정 템플릿 2종·유형/경험/편집 3단계, 순서 이동·문장 다듬기 제안·미리보기·증빙 체크, 목적별 활용 | 기존 확정 경험에서 초안 생성·저장·재열기 |
| 6 AI 상담 | 경험/자료 문맥 선택·동의, 실제 대화, 근거·검토 연결 | 키 미설정/에러/정상 응답; 임의 데이터 변경 없음 |
| 7 Drive | 서버 OAuth, Picker, 선택 파일 가져오기, export, 수동 동기화, 연결 철회 | 사용자별 토큰 격리, 중복·권한상실·삭제·새 버전 처리 |
| 8 통합 | Realtime 집계, 접근성, 오류 복구, 명시적 격리 데모, 문서/운영 점검 | 실제 계정으로 핵심 흐름 E2E, build·필수 테스트 통과 |

단계 0의 자료 누락은 해소됐다. 공식 문서 접근도 복구돼 Next.js·Supabase·Gemini·Google 지원 방식의 기본 검증을 완료했다. 설치 버전·Gemini 생성/임베딩 모델 및 파일 추출 지원은 단계 1~3에서 추가 확인한다. 앱 구조화·문서·마이그레이션 설계는 외부 키 없이 가능하다. 외부 호출의 성공 검증은 실제 자격증명 준비 후 수행한다.

## 초기 구조 후보
- app/: 로그인, 학생 화면, 서버 Route Handler.
- components/: 자료·경험·포트폴리오 UI. 그래프는 client-only 로딩.
- lib/supabase/: browser/server 세션 클라이언트, lib/auth/: 권한 검사.
- lib/ai/: 서버 Gemini 어댑터, schema 검증, 동의 검증. server-only 강제.
- lib/drive/: 서버 OAuth·토큰 저장·export·동기화. 공개 Picker 클라이언트는 별도.
- lib/materials/: 형식/크기 검증, 추출, 근거 위치.
- supabase/migrations/: 테이블·복합 FK·RLS·Storage 정책·집계.
- tests/: 권한/동의/실제 저장 흐름. docs/: 설계·검증 근거·설정 안내.

## 우선 수직 흐름
첫 구현 목표는 로그인 → PDF 또는 기존 텍스트 등록 → 동의 → 실제 경험 제안 → 학생 확정 → 근거 연결 → 포트폴리오 저장이다. 이어서 보완·상담·Drive를 연결한다. 모듈별 UI만 먼저 완성하고 데이터 연결을 미루지 않는다.

## 필수 검증
- 실제 파일/DB 저장, 재조회, 검색, 수정, 삭제, 입력 검증.
- 타 계정 접근·관계 연결·Storage·Realtime 누출 차단.
- AI 키 없음·API 실패·출력 schema 오류·가짜 근거·동의 취소 처리.
- 학생 편집 내용이 AI 재실행/Drive 동기화로 변경되지 않음.
- Drive 중복 가져오기/변경 없음/새 버전/권한 철회 처리.
- 실제 저장 이벤트로 대시보드 갱신, 포트폴리오 재열기, 상담 근거 확인.
- 데모가 실제 계정 DB나 Google 토큰/API 작업에 연결되지 않음.

외부 미설정은 연결 필요 화면과 구체적 안내로 남긴다. 모의 테스트는 모의임을 표시하며 실제 통합 성공의 근거로 삼지 않는다. 주기 동기화·대용량 처리·공개 공유는 필요한 런타임/보안 검증 이후 확장한다. MVP에는 수동 동기화를 실제로 제공한다.

## 자료 대조 후 범위와 검증 추가
- 텍스트 중심 구조화·임베딩 캐시를 우선한다. 사진/음성/영상 자동 분석, GNN/자동 군집화/GraphRAG는 발표 11쪽에 따라 초기 제외한다.
- 관심사 선택→관련 경험/근거→그래프 이동을 실제 데이터로 검증한다. 관계·패턴 제안 채택/수정/거절과 재분석 후 확정정보 보존을 검사한다.
- 포트폴리오 미확인 태그가 생성 자체를 막지 않으며 누락 사실을 AI가 만들어 넣지 않는지 검증한다. 프로젝트 순서 이동·미리보기·기관 직접 확인·체크리스트 재조회 포함.
- 대체서식은 참고 작성안 구현과 공식 제출 규칙 검증을 분리한다. 공식 양식 확인 전 제출 적합 판정·대학별 체크리스트 자동 생성을 제공하지 않는다.
- 발표 8·15쪽의 외부 배포·PC/모바일 사용자 테스트·피드백 반영·공개 문서/라이선스 검토를 통합 단계에 포함한다. 실제 게시·배포는 사용자 요청 범위와 환경 설정이 확보된 후 수행한다.

## 현재 화면 구현 상태
요청 화면 6종과 데모 저장/조회/편집 흐름은 구현했다. 단계 1의 앱 설치와 화면 검증을 진행했지만, 단계 2~7의 실제 인증·DB·AI·Drive 작업 완료를 의미하지 않는다. 실행 방법과 연결 지점은 [화면 실행 안내](06-running-and-validation.md)를 참고한다.
